# TempCleanup.ps1 (PowerShell 5.1)

Safe temp-file cleanup and startup-entry management script for Windows endpoints with dry-run support, per-file error handling, detailed logging, summary reporting, rollback support, and idempotent behavior.

## File Location
- Day3/TempCleanup.ps1

## What It Does
- Targets temp files under default locations:
  - `%TEMP%`
  - `%WINDIR%\Temp`
- Filters files older than a configurable age.
- Lists startup programs from:
  - Registry Run/RunOnce keys (HKCU, HKLM, WOW6432Node)
  - User and common Startup folders
- Can disable startup entries by name in cleanup mode.
- Skips locked files and logs the skip.
- Handles errors per file (continues processing).
- Logs every action to a timestamped log file.
- Creates rollback artifacts:
  - Backup copies of deleted temp files
  - Backup copies for disabled Startup folder entries
  - A CSV manifest for restoring files and startup changes
- Prints a summary at the end.

## Safety Model
- Dry run mode makes no changes and only logs what would be changed.
- Cleanup mode copies each file to rollback storage before deleting the original.
- Startup disable mode records rollback metadata for each disabled startup entry.
- Rollback mode restores both deleted files and disabled startup entries from a selected manifest.

## Parameters
- `-DryRun`
  - Cleanup mode only.
  - Lists files that would be deleted.
  - If `-Disable` is used, also lists startup entries that would be disabled.

- `-MinAgeDays <int>`
  - Cleanup mode only.
  - Minimum age threshold in days.
  - Default: `0`
  - Example: `-MinAgeDays 7` deletes only files older than 7 days.

- `-TargetPaths <string[]>`
  - Cleanup mode only.
  - Optional custom paths to scan instead of defaults.

- `-Disable`
  - Cleanup mode only.
  - Enables startup disable action.
  - Must be used with `-ProgramName`.

- `-ProgramName <string>`
  - Cleanup mode only.
  - Program name filter used with wildcard matching against startup entry name.
  - Example: `-ProgramName "OneDrive*"`

- `-OutputRoot <string>`
  - Optional.
  - Location for logs, rollback store, and manifest.
  - Default: `Day3\TempCleanupArtifacts`

- `-Rollback`
  - Switch to enter rollback mode.
  - Use together with `-RollbackManifest`.

- `-RollbackManifest <string>`
  - Rollback mode only (mandatory in rollback mode).
  - Path to a manifest CSV generated by a previous cleanup run.

## Usage Examples
- Dry run with defaults:
  - `powershell -ExecutionPolicy Bypass -File .\Day3\TempCleanup.ps1 -DryRun`

- Cleanup files older than 3 days:
  - `powershell -ExecutionPolicy Bypass -File .\Day3\TempCleanup.ps1 -MinAgeDays 3`

- Cleanup with custom targets:
  - `powershell -ExecutionPolicy Bypass -File .\Day3\TempCleanup.ps1 -MinAgeDays 2 -TargetPaths "C:\Windows\Temp","C:\Temp"`

- Dry run startup disable for matching program name:
  - `powershell -ExecutionPolicy Bypass -File .\Day3\TempCleanup.ps1 -DryRun -Disable -ProgramName "OneDrive*"`

- Disable startup entries by name and run cleanup:
  - `powershell -ExecutionPolicy Bypass -File .\Day3\TempCleanup.ps1 -Disable -ProgramName "OneDrive*" -MinAgeDays 1`

- Rollback from manifest:
  - `powershell -ExecutionPolicy Bypass -File .\Day3\TempCleanup.ps1 -Rollback -RollbackManifest ".\Day3\TempCleanupArtifacts\Manifest_20260805_130000.csv"`

## Idempotency Notes
- Running dry-run repeatedly is safe and produces no system changes.
- Re-running cleanup is safe:
  - Already removed files are skipped and logged.
  - Locked files are skipped and logged.
- Re-running startup disable is safe:
  - Entries already removed are skipped and logged.
- Re-running rollback is safe:
  - Existing destination files are overwritten by restored versions from backup.
  - Existing startup registry values are updated with stored command data.

## Important Operational Notes
- Rollback depends on backup files under `RollbackStore_<timestamp>` and the matching manifest.
- Do not delete rollback artifacts if you may need to restore files/startup entries.
- Administrative rights may be required for some system temp paths and all-users startup keys.
